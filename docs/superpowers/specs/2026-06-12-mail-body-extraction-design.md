# 메일 본문 포함 요약 & 수동 삭제 기능 설계

**작성일:** 2026-06-12  
**상태:** 설계 완료

---

## 목표

현재 메일 제목만으로 분석하는 방식을 개선하여, **메일 본문을 포함해서 분석**하고, 사용자가 **불필요한 메일을 수동으로 삭제**할 수 있도록 구현.

---

## 2단계 프로세스

### Phase 1️⃣: 메일 수집 & 요약

1. **메일 목록 스크롤**
   - Naver 메일 전체 목록을 스크롤해서 모든 미읽 메일 찾기
   - 현재: 상위 5개만 추출 → 변경: 전체 추출

2. **본문 추출**
   - 각 메일을 순차적으로 클릭
   - iframe에서 본문 텍스트 추출
   - 본문 로드 실패 시 제목만 사용

3. **AI 분석**
   - 제목 + 본문을 Gemini (gemini-2.5-flash)로 분석
   - 요약, 액션, 우선순위, 카테고리 추출

4. **메일 읽음 표시**
   - 요약 완료 후 메일을 "읽음" 상태로 변경
   - Naver 메일의 읽음 표시 UI 활용 (체크박스 클릭 또는 flag 제거)

5. **진행률 표시**
   - UI에 실시간 진행 상황 표시: "5/32개 메일 분석 중..."
   - 현재 처리 중인 메일 제목 표시

### Phase 2️⃣: 사용자가 수동 선택 & 삭제

1. **완성된 요약 목록 표시**
   - 모든 메일 요약 로드 완료 후 목록 렌더링
   - 각 메일 카드에 삭제 체크박스 추가

2. **사용자 선택**
   - 사용자가 불필요한 메일 체크박스 선택
   - UI에서 실시간 피드백 (체크 상태 표시)

3. **삭제 처리**
   - "삭제" 또는 "정리하기" 버튼 클릭
   - 선택된 메일을 목록에서 제거 (또는 숨김)

4. **최종 결과**
   - 선택되지 않은 메일만 표시
   - 정리된 요약 목록

## 기술 구현 범위

### Backend (Python/Flask)

#### `crawler.py` 수정
- `fetch_naver_emails()` 메서드 활용
  - 현재: Chrome 디버깅 포트에서 제목만 추출
  - 변경: 메일 클릭 → 본문 추출 → 읽음 표시

#### `app.py` 수정
- `/api/fetch-mails` 엔드포인트 개선
  - 메일 목록 전체 스크롤 (현재: 상위 5개만)
  - 각 메일의 제목 + 본문 사용
  - 진행률 정보 JSON으로 반환
  - 읽음 표시 처리

- 새 엔드포인트: `/api/delete-emails`
  - POST 요청으로 삭제할 메일 ID 수신
  - 메일 삭제/숨김 처리 (로컬 상태로만 관리 또는 Naver에 반영)

### Frontend (HTML/JavaScript)

#### 진행률 표시
- 로딩 중: "5/32개 분석 중..." 텍스트
- 현재 처리 메일 제목 표시
- 프로그레스 바 (선택사항)

#### 최종 목록 & 삭제 UI
- 각 메일 카드에 체크박스 추가
- "선택된 항목 삭제" 버튼
- 체크 상태 실시간 업데이트

## 에러 처리

| 상황 | 처리 방식 |
|------|----------|
| 본문 로드 실패 | 제목만으로 분석 진행 |
| 읽음 표시 실패 | 분석 결과는 유지, 메일은 미읽 상태 |
| 스크롤 중단 | 현재까지 수집된 메일만 분석 |
| 삭제 실패 | 사용자에게 알림, 상태 복원 |

## 성능 고려사항

- **시간 소요:** 메일 개수 × 2~3초 (예: 100개 = 3~5분)
- **메모리:** 모든 메일 본문을 메모리에 로드 (필요시 스트리밍 고려)
- **UI 블로킹:** 진행 중에도 UI 응답성 유지 (비동기 처리)
